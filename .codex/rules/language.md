# Project Language Rule

English is the canonical language for this repository.

- Write all source code, file and directory names, identifiers, variables, functions, classes, types, comments, tests, configuration, logs, error messages, developer-facing text, commit messages, and documentation in English.
- Runtime user-facing responses may use the user's preferred language when product behavior requires it.
- For every project-authored English Markdown file outside `.codex/`, create and maintain a Ukrainian translation with the same path and base name plus the `.ukr.md` suffix.
- Keep both Markdown versions synchronized in the same change. The English version is canonical when the versions differ.
- In Ukrainian translations, preserve code, identifiers, commands, environment variables, paths, product names, and API names exactly as written in English.
- Do not add Ukrainian prose to files other than `*.ukr.md`.
- Markdown files under `.codex/` do not require Ukrainian counterparts. Generated files, vendored files, dependencies, lockfiles, and third-party content are also exempt unless maintained directly by this project.
